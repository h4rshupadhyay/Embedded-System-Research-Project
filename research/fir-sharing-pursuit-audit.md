# Pursuit audit: exact-width FIR sharing software

20 October 2026. Independent skeptical assessment for a college original-contribution paper; FIR only, simulator only, publication optional. Read the existing findings, provenance, gap screen and accumulator-partition screen. No generator, optimizer or target experiment was implemented or rerun. The only new local calculation was arithmetic on saved coefficients.

## Verdict

**Conditional go for a bounded empirical investigation; no-go for committing to the current headline or a new-optimization-algorithm claim.** The existing probe is useful original experimental work. It does not yet establish that mixed-width transposed sharing wins against equally coefficient-specialized direct arithmetic. One small, material missing control can plausibly account for much of its strongest result. Close that comparison before choosing the paper's central claim. The existing findings' unconditional recommendation to proceed with paper development is premature on this evidence.

The college goal does not require inventing a theorem. A credible contribution could be new controlled evidence about when established representations and arithmetic choices work on this precise software target, with explanation and a reproducible artifact. That is different from significant field-level novelty. Neither a first-of-kind claim nor publication quality is certified here. More available time cannot resolve an unidentified contribution; the missing comparison can.

## Material missing control: narrow direct partial sums

The source confirms the concern. In [probe.py](fir-sharing-probe/probe.py), `certificates()` chooses `sum_width` from the full coefficient L1 bound. `generate()` uses that type for every `+=` in specialized direct and folded kernels. In [kernels.c](fir-baseline/kernels.c), `direct64` and `fold64` similarly maintain a wide accumulator throughout. The transposed competitors instead receive a separate range proof for each retained suffix. This is valid benchmarking of the listed implementations, but unequal arithmetic specialization when attributing the benefit to representation.

For the saved [minimum-phase48 coefficients](fir-baseline/selection-design.json), the full-int16 contract has `M=32768` and total L1 sum `72509`, so its sufficient absolute bound is `2375974912`, above `INT32_MAX`. However, split the *ordinary direct dot product* into these two contiguous coefficient groups:

| Coefficient indices, zero-based | L1 sum | Absolute bound |
|---|---:|---:|
| 0 through 1 | 12778 | 418709504 |
| 2 through 47 | 59731 | 1957265408 |

Both partial sums and every accumulation prefix fit int32. Every individual Q15 product fits int32 too. Compute the two groups with native-width sums, convert each completed sum to int64, add once, and apply the existing quantizer once. The triangle inequality proves this exact for every allowed stream; it uses no intermediate truncation, wrapping or observed-sample assumption. This is a deduction from the stored coefficients and ordinary integer arithmetic, not a new algorithm. It uses the same tail bound that makes 46 transposed states narrow.

This control replaces dozens of wide additions with narrow additions while retaining the direct history organization. It might remove the headline advantage; whether it actually does depends on generated instructions, loads, scheduling and spills, so **no speedup or reversal is predicted without measurement**. It is a material missing control even without any published paper implementing this exact split: a fair comparator can directly apply the same elementary proof already granted to the candidate. The earlier [partition screen](fir-next-direction-screen.md) had already recommended safe chunks when the full sum needs widening.

The reported 32.94% advantage remains an observation against the tested CMSIS control, not a demonstrated advantage over the strongest easy exact specialization. The 12/24 winner count similarly remains conditional on the tested set. Adding this control need not affect groups already certified globally int32. [Existing measured results and limitations](fir-sharing-findings.md).

## What remains a useful empirical question

The defensible question is: **after applying equal exact range information to competing FIR forms, which source representation produces the best complete streaming implementation on the pinned scalar target, and which costs explain the result?** The literature above gives reasons to expect interactions, not the answer for this contract and backend.

The current same-graph eager/demand comparison already supplies an informative controlled observation. The ordinary-product/transposed control and state-width ablation prevent crediting the whole library gap to Hcub; those are strengths. However, source emission order helping one backend is evidence of code-quality sensitivity, not proof of a new scheduling algorithm or compiler defect. Three chosen designs and two compilers can support a case study, not prevalence estimates or a transferable selection rule. Small modeled-energy rankings need to remain model-specific. [Probe findings](fir-sharing-findings.md).

## Minimal decision gate, before optimizer or paper commitment

1. **One missing-control test first:** add only the two-group exact direct control above for minimum-phase48/full-int16. Fix its partition before measurement. Use both existing compilers and both block sizes, the existing complete stream, final short calls, zero initialization and quantizer. No partition search or optimizer is needed. Verify arbitrary-precision equality, state retention, every prefix bound and C intermediate arithmetic; inspect the assembly to confirm the intended narrow arithmetic survived compilation.
2. Compare it with the strongest existing nontransposed control, ordinary mixed-width transposition and demand Hcub. Report target event/cycle estimates, model energy, code, frame and retained storage. This four-configuration comparison decides whether the strongest motivating example survives the obvious fairness objection. If it fails, revise the headline immediately; do not retain the old percentage as superiority over specialized direct FIR.
The decision gate is this one missing-control comparison, not an expanded optimizer or benchmark campaign. If the investigation subsequently proceeds to bank-level claims, those claims will need equally safe chunks for the other globally-wide contracts and valid folded chunks where applicable. That later fairness requirement is not a recommendation to expand the matrix now. Preserve negative cases and the ordinary transposed control, and do not treat these already-inspected designs as fresh validation.

**Pass:** a meaningful benefit or tradeoff survives fair controls and has a specific cost explanation, or the corrected comparison supports a useful, clearly framed negative result about the apparent sharing advantage. That can justify a college empirical paper with explicit prior-art positioning; a new theorem is unnecessary. **Fail for this proposed central contribution:** the attractive result disappears into obvious baseline narrowing and the remainder only shows that scheduling sometimes changes spills, without a coherent additional finding. Then keep the artifact as an engineering result and select a stronger paper question. Either outcome is useful; this audit authorizes no general optimizer build.
