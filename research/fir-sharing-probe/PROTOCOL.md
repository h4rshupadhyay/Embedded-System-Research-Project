# Exploratory FIR sharing/state-cost probe

20 October 2026. Throwaway numerical/target research fixture, not a production library or new algorithm. This protocol is written before evaluating the generated target kernels. The user approved the bounded probe described in `../fir-direction-decision.md`.

Question: can established constant-product sharing across outputs improve complete exact FIR execution after exact state widths, register pressure and state traffic are included? A speedup alone does not establish novelty.

Freeze three existing designs from `../fir-baseline/selection-design.json`: symmetric `speech_lp48`, symmetric `vibration_bp192`, and nonsymmetric `speech_minphase48`. No coefficients change. Use the first 257 existing `adc_raw` samples, with zero history and a short final block, under both full-int16 and ADC11 guarantees. These reuse actual input values; they are not independent application trials. Blocks are 1 and 64, GCC 10.3.1 and 15.2.Rel1, Cortex-M0 Thumb, `-O2`, no LTO. The reference remains `clip_int16(floor(exact_sum/32768))` for every input sample. Do not append convolution-tail samples the reference did not request.

Controls: strongest admitted generic direct/folded kernels; default and loop-unrolled standard/fast CMSIS Q15 where safe; coefficient-specialized unrolled direct/folded code; and the same transposed state equations with ordinary constant multiplications. Sharing controls use independent canonical signed-digit (CSD) expressions and the authors' original Hcub generator. Hcub is an existing method, not our contribution. Save its raw output, source archive hash, invocation and license. Compare eager graph emission and dependency-driven emission in stage-consumption order as an established scheduling control. No coefficient/seed/schedule search after costs are seen.

For a transposed FIR, `output = Q(h[0]*x + old_state[0])`; ascending updates are `state[i] = h[i+1]*x + old_state[i+1]`, with final state `h[last]*x`. Prove each suffix state's width from its actual coefficient sum and the declared input magnitude; use 32 or 64 bits as required. Certify graph identities and each shifted/add/sub intermediate. Signed left shifts are replaced with safe exact arithmetic; right shifts in Hcub graphs must be provably divisible before exact C division is used. Verify final transposed state against independently reconstructed suffix convolutions, not against raw direct-history bytes.

First record a justified optimistic state-traffic/arithmetic cost for the specified transposed realization. The screen deliberately omits spills, control and quantization; it is not a lower bound on all possible FIR algorithms. If all candidate realizations are already dominated by the measured strong baseline, stop without a general optimizer. Otherwise compile just the diagnostic kernels above.

Count complete finite-stream processing, including calls, loop/tail handling, input/state/output movement and all recurring state updates. Coefficients/code remain in Flash; data/state/output in SRAM. Initialization, reference checking and printing are outside the ROI as in the audited baseline. Reuse its checked instruction subset, Arm-table zero-wait-state timing estimate and published 20 MHz/prefetch-off/zero-wait energy model. Single-cycle MUL is the pinned model; no generic claim about every Cortex-M0 multiplier implementation. Raw simulator ticks remain diagnostic. No hardware energy or timing claim.

Correctness gates: graph algebra/range certificates; host undefined-behavior-sanitized checks for signed extrema, saturation, nonsymmetric orientation, initial zeros and mixed block partitions; target output equality, retained-state equality and state/output guards. Full-int16 generated kernels also receive an adversarial edge stream. Save binary, source, stdout/event/disassembly hashes, state bytes and compiled code/stack-usage diagnostics. Stack-usage diagnostics are compiler reports, not a hardware high-water measurement.

Decision: reject any exact kernel with a mismatch. Reject a new-method claim if observed gains are explained by ordinary coefficient specialization, established MCM or graph scheduling. Reject this realization family as a main optimization direction if complete cost loses to strong controls or optimistic headroom is too small to justify it. An actual go requires a specific reproducible inadequacy in strong existing approaches and a further closest-work check; a new target, extra rows or a better-than-naive kernel is insufficient. New empirical guidance could qualify without a new theorem, but must be substantial and differentiated.

Review correction, 20 October: the source-level estimate originally charged each state-word transfer as a separate load/store instruction. LDM/STM grouping and register retention can reduce that cost even for the same equations. The recorded scalar-access estimate is therefore **not an optimistic floor and cannot reject a candidate**. No candidate was excluded using it; all specified target cases were executed. Decisions use complete counted execution. This correction changes diagnostics and provenance metadata only; generated kernels and saved target traces are independently reconstructed and checked unchanged. It is a post-run methodological correction, not an additional held-out experiment.
